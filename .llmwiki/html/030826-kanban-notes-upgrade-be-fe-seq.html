T1 · Migration schema mới (users/sessions/boards/...) + backfill Claude Code

Gộp 2 rủi ro: mất note cũ khi chuyển từ column_key tự do sang board_id/column_id, và thiết kế sai schema auth mới. kanban_users/kanban_sessions tách biệt hoàn toàn khỏi OwnerPassword (hằng số Go) để không tạo 2 nguồn sự thật về quyền owner — is_owner trên bảng chỉ mang tính hiển thị, quyền admin thật vẫn đến từ biết đúng owner712002.

T2 · auth_kanban.go — register/login/session + admin approve Claude Code

Phần nhạy cảm bảo mật nhất: verifyKanbanAccess phải là superset đúng nghĩa của verifyOwnerPassword cũ — owner không bao giờ tự khoá mình ra khỏi board. Endpoint admin approve/reject cố tình không chấp nhận session user thường (dù đã approve), chỉ chấp nhận owner712002 — nếu không, một user có thể tự approve tài khoản khác, phá vỡ approval flow.

Login khi status='pending' hoặc 'rejected' → 403, không tiết lộ lý do chi tiết (tránh dò username tồn tại).

T3 · notes.go — đổi gate + mở rộng field + subtask/comment Claude Code

Comment giờ có "tác giả thật" — author_user_id lấy từ identity đã xác thực bởi verifyKanbanAccess, không phải trường tự do từ client (tránh mạo danh). Đổi gate chỉ ở đúng 1 điều kiện gọi hàm, giữ nguyên toàn bộ logic 401 xung quanh — surgical change, không viết lại handler.
