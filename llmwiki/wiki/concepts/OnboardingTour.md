# OnboardingTour
**Type:** concept
**Tags:** onboarding, tour, architecture, walkthrough

11-step guided tour through the Cozyroom codebase — from project overview down to K8s deployment. Each step references the key file(s) and explains what role they play. Generated by `orca-onboard` Phase 1.5 (Claude main thread, 2026-06-19).

## Step 1 · Project Overview

**Files:** `README.md`, `CLAUDE.md`, `docker-compose.yml`

Cozyroom is a self-hosted personal media server: music with gapless playback, AI assistant via MCP, YouTube stream/download, HLS video, ebooks/comics. React frontend with Spotify-like purple/glassmorphism UI. Deployed on K3s (3 WSL2 nodes) with Citus distributed Postgres. `CLAUDE.md` encodes LLM behavioral rules — production DB path, simplicity-first coding, surgical change policy — always read it first before touching the codebase.

## Step 2 · Server Entry Point

**File:** `backend/cmd/server/main.go`

This file is the composition root. It wires all dependencies: opens the Postgres connection pool, constructs repository implementations, builds the usecase layer, registers the HTTP router (`routes.go`), launches background goroutines (library scan, enrichers, trending fetch), and starts cron + chat bots (Telegram, Discord, Teams). If you're tracing where something is initialized or what depends on what, start here.

## Step 3 · HTTP Routing & Middleware

**Files:** `backend/internal/api/routes.go`, `backend/internal/api/handler.go`

`routes.go` registers ~60 endpoints grouped by domain: `/api/artists`, `/api/albums`, `/api/tracks`, `/api/stream/:id`, `/api/youtube/*`, `/api/ai/*`, `/api/covers/:id`, `/api/playlists`, `/api/trending`, `/api/scan`, `/api/stats`, `/api/lyrics/:id`, `/api/video/*`, `/api/ebook/*`, `/api/comics/*`. Two middleware wrap all handlers: `metricsMiddleware` (Prometheus counters + latency histograms) and `panicRecovery`. Non-API routes fall through to the SPA handler which serves `frontend/dist/index.html`.

## Step 4 · Database & Repository Layer

**File:** `backend/internal/db/db.go`

`db.go` wraps `pgx/v5` with a connection pool (MaxConns=20) and query helpers. All Postgres repositories in `backend/internal/repository/postgres/` implement domain interfaces from `backend/internal/domain/` — handlers never touch SQL directly. Citus distributed Postgres: coordinator at `db-adapter` (HAProxy), primary worker at `postgres`, replica at `postgres-standby`. `enable_repartition_joins = on` in `postgresql.auto.conf`.

## Step 5 · Library Scanner

**File:** `backend/internal/library/scanner.go`

Walks `musicPath` recursively. For each audio file: reads tags via `dhowden/tag` (artist, album, title, year, genre), derives deterministic 8-byte hex IDs via `SHA256(lowercase(trim(s)))[:8]`, extracts embedded cover art to `coversDir/<albumID>.jpg`, upserts artist/album/track to Postgres (`ON CONFLICT(id) DO NOTHING` for albums/artists — enriched covers survive re-scans). YouTube files detected by `len(baseName) == 11` (YT ID length): if cover missing, launches `go downloadYTThumbnail(baseName, dest)` goroutine which tries `maxresdefault → hqdefault → mqdefault` from `img.youtube.com/vi/<ytid>/<size>.jpg`.

## Step 6 · Audio Streaming & Transcoding

**File:** `backend/internal/transcode/transcode.go`

`GET /api/stream/:id` serves byte-range audio. For MP3/AAC/OGG: serves file directly with Range header support. For FLAC/WAV/AIFF: `transcode.go` pipes through `ffmpeg -i <input> -c:a libopus -f webm -` streaming to HTTP. HLS module (`backend/internal/hls/`) handles video segmentation (.m3u8 + .ts). Cover art via `cover()` handler with `singleflight` dedup and JPEG resize. Critical: nginx sidecar must have `proxy_buffering off` or audio streams cause OOMKill.

## Step 7 · YouTube Integration

**File:** `backend/internal/api/youtube.go`

`YouTubeHandlers` struct holds `db`, `musicPath`, `ytDownloadPath`, `coversDir`, `cloakProxyURL`. Three flows:
- **Search:** `yt-dlp --flat-playlist -j` → parse JSON → `[{id, title, uploader, duration}]`
- **Stream:** `yt-dlp --get-url` → wrap through cloak-proxy → 4h signed-URL cache → return stream URL
- **Download:** yt-dlp writes to `ytDownloadPath`, copies thumbnail `dlPath/<id>.jpg → coversDir/<albumID>.jpg`, calls `IndexFileWithMetadata` to register in DB

`albumID = id8hex(id8hex(uploader) + title)` — same `id8` function as scanner.go.

## Step 8 · AI Agent & MCP Tools

**Files:** `backend/internal/mcp/registry.go`, `backend/internal/api/ai.go`

`mcp/registry.go` defines 23 tools as JSON Schema objects. `ai.go` runs the agentic loop: prepend system prompt → call LLM (Claude 3.5 Sonnet or OpenRouter model) → dispatch `tool_calls` to registry → append `tool_result` → loop (max 12 rounds). Persistent key-value memory in `ai_memory` table. Token usage tracked per-model in `ai_usage` table (feeds `AIStatsPage`). Tools include: `play_track`, `search_library`, `web_search` (DuckDuckGo via cloak proxy + chromedp), `browse_url`, `get_lyrics`, `read_memory`, `write_memory`, `get_trending`, and 15 more.

## Step 9 · Frontend Player State

**File:** `frontend/src/PlayerContext.tsx`

Global player state via React Context. Holds: `track` (active track), `queue` (smart radio or explicit playlist), `ytStreamUrl` (resolved YT stream URL), `volume`, `progress`, `duration`, `isPlaying`, `lyrics`. Gapless: dual Audio elements (`audioRef`/`nextAudioRef`), preloads next track at 90% of current duration, swaps at track end. Critical: `trackRef.current = track` must sync BEFORE `setTrack(track)` — async useEffect sync causes stale closure in `timeupdate` handler → 0:00 duration display. `localStorage` persists queue + volume.

## Step 10 · Frontend Pages & Components

**Files:** `frontend/src/pages/AIAssistantPage.tsx`, `frontend/src/components/PlayerBar.tsx`, `frontend/src/components/RadialNav.tsx`

Pages: `ArtistsPage` (artist grid, mirror reflection CSS), `AlbumDetailPage` (tracklist, glassmorphism covers), `AIAssistantPage` (streaming chat, tool-call display, model selector), `TrendingChartMode` (GitHub trending + Nightingale rose chart), `PlaylistsPage` (CRUD + drag-reorder), `VideoPlayerPage` (hls.js), `EbookReader`, `ComicsReader`, `SearchPage`.

Components: `PlayerBar` (bottom persistent bar, YT cover retry 4× with 2/4/6/8s backoff — because backend returns 503 on thumbnail fail so `onError` fires), `RadialNav` (polar segment nav), `NowPlayingSheet` (mobile swipe-up).

## Step 11 · K8s Deployment

**Files:** `k8s/backend.yaml`, `k8s/cloudflared.yaml`

Backend: Go binary pod with PV mounts at `/data` (covers, HLS), `/youtube` (yt-dlp), `/music` (read-only NFS). Frontend: nginx serving React dist + SW. `cloudflared.yaml`: cloudflared + nginx sidecar (`proxy_buffering off; proxy_request_buffering off; memory 128Mi`) — CF remote config hardcodes `localhost:18080`, sidecar MUST exist. Deploy via `deploy-k8s-frontend` skill (build → push to `100.88.197.64:5000` registry → rollout restart). Prometheus + Grafana in `observability/` namespace.
