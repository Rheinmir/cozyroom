Citus Distributed Postgres

01 · Tiếp cận sai

6 tiếp cận bị loại trừ

Trước khi chọn Citus, 6 hướng khác được đánh giá và loại vì không đáp ứng yêu cầu distributed thực sự.

#Tiếp cậnLý do loại
❌1Streaming replicationCopy toàn bộ data — nhân bản không phải phân tán
❌2Separate DB per serviceData split, không có unified view
❌3DB trong K8s podUser reject
❌4Single centralized PostgresKhông distributed, SPOF
❌5Manual routing trong app codeCoupling cứng, app phải biết topology
❌6FDW thuầnQuery planning kém, không true sharding
02 · Kiến trúc

Citus trên 3 physical nodes

Coordinator nhận mọi query từ Backend, phân phối sang workers qua Tailscale. Backend không đổi gì ngoài DB_URL.

03 · Phân loại bảng

Distributed vs Reference tables

Distributed tables được sharded theo id (hash). Reference tables được replicated xuống tất cả nodes để join nhanh.

Distributed (sharded by hash id)
shard tracks
shard albums
shard lyrics
shard ebooks
shard comics
shard playback_progress
Data lớn → phân tải across workers
Reference (replicated to all nodes)
ref playlists
ref playlist_tracks
ref settings
ref artists
ref lyrics_cache
Data nhỏ, join thường xuyên → replicate tất cả

Risks còn lại
  • ⚠ Coordinator SPOF: Node-1 down → all queries fail. Mitigaton: Citus HA coordinator — có thể add sau
  • ⚠ Cross-shard joins: Queries join distributed tables chậm hơn local joins. Mitigation: reference tables đã giảm thiểu
  • ⚠ Tailscale latency: Cross-node queries thêm ~1-2ms. Acceptable cho music app
