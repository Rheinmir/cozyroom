T1 · Backend — health watcher với ngưỡng chống nhấp nháy Claude main

Package internal/health chạy trong mỗi backend pod, poll trạng thái sống của từng DB node mỗi 5 giây qua interface LivenessSource có hai implementation: với CockroachDB đọc crdb_internal.gossip_liveness (một query trả trạng thái mọi node), với Postgres hiện tại thì ping từng node — nhờ interface này feature chạy được ngay cả trước khi migration CRDB hoàn tất.

Một network blip đơn lẻ không được phép làm UI nhấp nháy: watcher chỉ tuyên bố một node down sau 2 lần poll fail liên tiếp (tức ~10 giây trễ tối đa), và tuyên bố sống lại ngay lần poll thành công đầu tiên. Khi trạng thái đổi, watcher phát event vào channel nội bộ để hub WebSocket (T2) broadcast — không có consumer nào tự poll lại DB.

T2 · Backend — WebSocket hub qua CF Tunnel 2 lớp nginx Claude main

Endpoint /api/ws/cluster-health dùng gorilla/websocket — thư viện đã có sẵn trong go.mod (indirect, nâng thành direct). Hub giữ danh sách client, broadcast JSON {nodes, unavailable_track_count, ts} mỗi khi watcher phát event, kèm heartbeat 30 giây để giữ kết nối sống qua Cloudflare. Hub stateless: watcher chạy trong từng pod đọc cùng nguồn liveness, nên client nối vào pod nào cũng nhận đúng cùng trạng thái — không cần đồng bộ giữa các pod.

Điểm rủi ro nhất không nằm ở Go mà ở hạ tầng: request đi qua cloudflared → nginx sidecar → frontend nginx → backend, và WebSocket handshake cần header Upgrade/Connection được forward đúng ở cả hai lớp nginx — thiếu một lớp là fail âm thầm. Đây là lý do draft nêu SSE làm phương án thay thế (Quyết định 4): SSE đã chạy production trong chatStream với zero config mới.

T3 · Shard mapping — bài hát nào thuộc node nào Claude main

Đây là nơi Quyết định 3 (I1/I2) đổ vào code. Với I2 — media locality (khuyến nghị): bảng mới media_hosts(host, path_prefix, node_name) khai báo host nào giữ file dưới prefix nào; khi watcher báo node down, backend query tracks WHERE file_path LIKE prefix || '%' để ra danh sách bài unavailable. Metadata vẫn sống nhờ CRDB RF=3 — chỉ stream là chết. Hiện tại toàn bộ media nằm trên một host duy nhất nên hôm nay chỉ có một shard; bảng này đón sẵn ngày media rải ra nhiều node như hướng "partial library per node" đã ghi từ draft 160626.

Với I1 — metadata sharding thật (RF=1): phải đọc crdb_internal.ranges để biết range nào có lease trên node chết — phức tạp hơn đáng kể và vứt bỏ lợi ích HA của CRDB, chỉ hợp lý khi mục tiêu là dung lượng chứ không phải HA. Kèm theo task này là endpoint REST GET /api/cluster/health trả snapshot đầy đủ, để lần load trang đầu tiên FE có trạng thái ngay trước khi WebSocket kịp nối.

T4 · Frontend — ẨN track unavailable + PlayerContext skip Claude main

Quyết định đã chốt của user: dữ liệu vẫn giữ nguyên trong DB, nhưng track thuộc host down bị ẩn hoàn toàn khỏi UI — không gray-out, vì bấm vào cũng không có gì phát ra. Khuyến nghị filter ngay ở backend query để mọi endpoint (list, search, album detail) nhất quán và FE không phải vá từng component; album/artist trống sau filter cũng ẩn theo (cascade). Hook mới useClusterHealth nối WebSocket với reconnect backoff + jitter (chống reconnect storm khi backend rollout 3 pod), seed trạng thái ban đầu từ snapshot REST của T3, và hiện banner "⏳ N bài tạm ẩn — node X down" để người dùng hiểu vì sao thư viện vơi đi thay vì tưởng mất dữ liệu.

Phần nhạy cảm nhất là PlayerContext.tsx — shared core mà toàn bộ player phụ thuộc: queue và smart radio phải skip track unavailable để không nhét bài chết vào hàng đợi. Theo đúng rule CLAUDE.md, bước này chạy frontend-index trước để map chính xác component nào bị ảnh hưởng, rồi đi qua impact-check + safe-change. Service worker không liên quan (WebSocket không đi qua Workbox) — không có rủi ro sw2.js.

T5 · Verify end-to-end — kill node thật, UI tự phản ứng Claude main + user

Bài nghiệm thu chạy trên cluster thật với user xác nhận trước: tắt một DB node khi site đang mở trong browser. Trong vòng tối đa 10 giây (2 chu kỳ poll), không cần reload, đúng danh sách bài thuộc shard đó phải biến khỏi mọi list/search (album rỗng ẩn theo) và banner hiện số bài đang ẩn — trong khi bài thuộc node khác vẫn browse và phát bình thường, smart radio không nhét bài chết vào queue. Bật node lại: UI tự phục hồi trong 10 giây, banner biến mất.

Đồng thời kiểm tra chống reconnect storm: rollout lại backend 3 pod trong lúc có nhiều tab đang mở, các client phải reconnect rải rác (jitter) và nhận cùng trạng thái từ bất kỳ pod nào. Kết quả — timing, screenshot banner, log hub — ghi vào wiki làm bằng chứng.
