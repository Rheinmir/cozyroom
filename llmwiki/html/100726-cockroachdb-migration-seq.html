T1 · Code compat — lease table thay advisory lock Claude main

Audit toàn bộ code backend cho thấy CockroachDB tương thích gần như hoàn toàn: driver là database/sql + pgx qua một DATABASE_URL duy nhất, search chỉ dùng ILIKE thuần (CRDB hỗ trợ native), schema trong migrate() là DDL chuẩn, và dòng CREATE EXTENSION pg_trgm đã tự tolerate lỗi từ trước. Điểm không tương thích cứng duy nhất là enricher/aitrends.go: hàm pg_try_advisory_lock(hashtext('ai-enrich')) — CockroachDB không hỗ trợ cả advisory lock lẫn hashtext.

Giải pháp là một lease table: bảng enrich_lease(key, holder, expires_at), pod nào INSERT ON CONFLICT thành công (hoặc UPDATE được dòng đã hết hạn) thì giữ quyền chạy EnrichWithAI — giữ nguyên mục đích chống 3 pod chạy trùng của fix 220626. Khác biệt ngữ nghĩa cần lưu ý: lock cũ nhả theo session, lease mới nhả theo TTL, nên TTL phải dài hơn thời gian enrich tối đa. Ngoài ra CRDB mặc định isolation serializable nên write có thể trả lỗi retry 40001; khuyến nghị đặt READ COMMITTED (CRDB ≥23.2) vì app này gần như không có write contention — ít sửa code nhất.

T2 · Dựng cluster 3 node — precondition: node 3 sống Claude main + user

CockroachDB dùng Raft consensus nên cần quá bán số node để hoạt động: cluster 3 node chịu được mất 1 node, nhưng cluster 2 node thì mất bất kỳ node nào cũng sập — tệ hơn cả hiện tại. Vì rhein-e2144g đang NotReady, hồi sinh node 3 (hoặc thêm máy khác) là điều kiện tiên quyết cứng trước khi làm bước này. Topology khuyến nghị là bare metal trên 3 host WSL2 nối qua Tailscale, khớp triết lý đã ghi trong ADR: "DB nên chạy bare metal, stateless apps trong K8s"; K8s chỉ giữ một Service/Endpoints trỏ ra ngoài.

Checklist bắt buộc trước khi cockroach init: bật time-sync trên cả 3 host — CRDB tự kill node khi clock lệch quá 500ms, và WSL2 nổi tiếng trôi clock sau khi máy sleep. Cấu hình homelab: --cache .25 --max-sql-memory .25, mỗi node cần tối thiểu ~2GB RAM. Verify của task này chính là bản chất của CRDB: tắt thử 1 node ngay sau khi dựng, cluster còn lại vẫn nhận query.

T3 · Migrate data — copy, không move Claude main + user giám sát

Nguyên tắc tối thượng của bước này lấy thẳng từ rule bảo vệ DB trong CLAUDE.md: Postgres không bị đụng vào. Schema không cần dump — backend tự tạo qua migrate() (CREATE TABLE IF NOT EXISTS) ngay lần đầu kết nối CRDB. Data thì pg_dump --data-only từ Postgres rồi import vào CRDB; dữ liệu metadata nhỏ (dưới 10GB PV, thực tế nhỏ hơn nhiều) nên import một lần là xong, không cần công cụ CDC phức tạp.

Bằng chứng hoàn thành là phép đối chiếu máy móc: SELECT count(*) từng bảng trên cả hai phía phải khớp 100%, cộng vài spot-check nội dung (track bất kỳ, playlist bất kỳ). Chỉ khi khớp mới được sang T4. Trong suốt quá trình, app vẫn đang chạy trên Postgres — người dùng không thấy gì khác lạ, và nếu có gì sai thì đơn giản là xoá database CRDB làm lại, không có rủi ro nào chạm vào dữ liệu thật.

T4 · Switch traffic — db-adapter đổi ruột, giữ tên Claude main

Backend hiện kết nối postgres://...@db-adapter:5432/cozyroom — tên Service db-adapter chính là điểm switch đẹp nhất: giữ nguyên tên, đổi ruột từ PgBouncer (chỉ trỏ được 1 host) sang HAProxy round-robin qua 3 node CRDB. Backend DATABASE_URL gần như không đổi, chỉ rollout lại pod là ăn kết nối mới. CRDB không cần connection pooler kiểu PgBouncer vì mỗi node tự xử lý pool nội bộ tốt.

Rollback là một lệnh duy nhất: trỏ db-adapter ngược về postgres:5432 — vì Postgres vẫn đang chạy nguyên vẹn ở T3, cửa thoát hiểm luôn mở trong suốt quá trình cutover. Smoke test sau rollout chạy trên chính music.giatbh.io.vn: browse, search, play, playlist, AI chat, trending.

T5 · Chaos verify — HA thật, không thao tác tay Claude main + user

Đây là bài kiểm tra mà kiến trúc Postgres primary/standby hiện tại chưa bao giờ vượt qua (Task 4 của draft 160626 vẫn pending): tắt hẳn một node database khi site đang chạy, và không ai phải làm gì cả. Với CRDB, Raft tự bầu leader mới cho các range nằm trên node chết trong vài giây; HAProxy health check loại node chết khỏi rotation; backend không thấy gì ngoài vài query retry.

Kịch bản đo: tắt node → browse + search + write (tạo playlist, play track) phải hoạt động bình thường trong vòng 10 giây; bật node lại → tự rejoin, ranges rebalance, dashboard 3 node xanh trở lại. Kết quả (log HAProxy, screenshot dashboard, timing) ghi vào wiki làm bằng chứng đóng SPOF saga từ 160626.
