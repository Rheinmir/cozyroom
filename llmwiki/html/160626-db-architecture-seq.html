Database Architecture Review

Phân tích SPOF tại Postgres primary, đề xuất Adapter Layer giữa Backend và DB, so sánh 3 pattern: Patroni / DB Adapter / Docker Compose per node.

01 · Hiện trạng

SPOF tại Postgres Primary

Backend 3 pod nhưng đều kết nối trực tiếp vào 1 Postgres primary — "HA giả". Primary làm 2 vai trò: storage + aggregation hub. Standby không auto-promote.

Vấn đề cốt lõi
  • ⚠ Primary làm cả storage lẫn aggregation hub
  • ⚠ Không có layer routing/failover giữa Backend và DB
  • ⚠ Standby không auto-promote — promote tay khi Primary chết
  • ⚠ hostPath: /tmp/ → mất data khi pod/node reboot
Constraint thực tế
  • 🏠 Media (/mnt/f/music,Films,Ebooks) chỉ ở rhein-13700hxes
  • 📦 Backend locked nodeSelector → hostPath media
  • ❌ rhein-e2144g: NotReady
  • 📡 Distributed DB ≠ HA thực sự nếu không có distributed storage
02 · Adapter Layer

Target topology — Adapter giữa Backend và DB

Adapter đặt giữa Backend và Postgres nodes, không phải trước Client. Backend chỉ đổi 1 env var: DB_HOST=db-adapter. Không đổi query logic, không đổi schema.

ResponsibilityMô tả
Query routingTrack X trên Node nào → gửi query đúng node
AggregationSELECT * FROM artists WHERE name LIKE '%..%' → fan out tất cả nodes, merge result
FailoverNode1 down → không route về đó, trả partial result từ các node còn lại
Health checkPing các Postgres node định kỳ, cập nhật routing table
StatelessKhông giữ session/state → scale horizontal, không tạo SPOF mới
03 · So sánh Pattern

3 Pattern triển khai

Mỗi pattern có trade-off về effort, HA thực sự, và complexity ops. Pattern B là recommended cho long-term.

Pattern A — Patroni auto-failover (ngắn hạn)
Backend ×N → HAProxy → Patroni cluster
                    ├── Primary ←streaming→ Standby
                    └── auto-promote khi Primary chết (~30s)
Effort: Trung bình DB HA ✓ Chưa distributed
Pattern B — DB Adapter ✅ Recommended
Backend ×N → db-adapter ×N (stateless)
                ├→ Postgres @Node1
                └→ Postgres @Node2
Effort: Cao True distributed ✓ No new SPOF
Pattern C — Docker Compose per node + Nginx upstream
Node1: docker compose (backend + postgres) + nginx
Node2: docker compose (backend + postgres) + nginx
Cloudflared → Nginx upstream (round-robin)
Effort: Trung bình Passive HA (failover chậm) Mất K8s orchestration
04 · Recommendation

Kế hoạch thực hiện

2 giai đoạn: ngắn hạn giảm downtime ngay, dài hạn true distributed.

Giai đoạn 1 — Ngắn hạn (làm ngay)
  • done Fix Postgres hostPath /tmp/ → /var/lib/
  • done Pattern A: Patroni auto-failover
  • done Alert Telegram khi Primary down
Giai đoạn 2 — Dài hạn
  • pending Build db-adapter (Go, stateless, Deployment ×N)
  • pending Mỗi node có Postgres riêng, Adapter giữ routing table
  • pending Backend chỉ đổi DB_HOST=db-adapter
  • pending HA verify: kill primary, check service còn sống
Về "phải dùng DB gì": Không phải về loại DB — đây là vấn đề kiến trúc vai trò. Postgres là đúng. Chỉ cần tách: DB = lưu trữ thuần tuý · Adapter = routing + aggregation + failover logic.
