T1 · Migration bảng kanban_notes Claude Code

Bảng mới hoàn toàn độc lập với schema hiện có — không khoá ngoại tới track/album/artist, vì note là dữ liệu tự do của riêng owner. Dùng đúng convention timestamp Postgres đã thấy ở các bảng khác trong db.go (EXTRACT(EPOCH FROM NOW())::INTEGER) để nhất quán, và column_key dạng text tự do thay vì enum cứng để giữ migration tối giản nhất có thể.

T2 · Backend handlers notes.go — gate cả GET Claude Code

Điểm khác biệt quan trọng nhất so với Playlists: GET /api/notes cũng phải gọi verifyOwnerPassword, vì đây là dữ liệu riêng tư — không giống playlist vốn công khai. Bỏ sót bước này là lỗi bảo mật thật: ai gọi thẳng curl không kèm mật khẩu sẽ đọc được toàn bộ note riêng tư của owner.

T3 · Frontend API client api.ts OpenCode

Lớp mỏng bọc quanh fetch, lặp lại đúng khuôn mẫu các hàm API khác đã có trong file — tự đính header X-Owner-Password lấy từ state mật khẩu đã nhập ở NotesPage. Vì tính chất lặp-khuôn-mẫu rõ ràng, việc này giao cho CLI rẻ hơn xử lý.

T4 · Trang NotesPage.tsx — gate trước khi render Claude Code

Nguyên tắc quan trọng: gate trước khi render, không phải "render rồi che bằng CSS". Nếu chỉ ẩn nội dung bằng overlay mờ trong khi component con vẫn gọi API lấy dữ liệu, dữ liệu vẫn nằm trong bộ nhớ trình duyệt và lộ qua DevTools dù giao diện trông như đã khoá. listNotes() chỉ được gọi sau khi state mật khẩu đã xác nhận đúng.

Kéo-thả dùng HTML5 Drag and Drop API gốc (không thêm dependency mới) cho desktop, kèm 2 nút mũi tên trái/phải trên mỗi card làm phương án thay thế cho thao tác chạm trên mobile — một đánh đổi tường minh đã nêu trong proposal, không phải thiếu sót.

T5 · Wire routing + Sidebar + verify thật Claude Code

Bước cuối là bằng chứng thật rằng cả hai lớp gate (UI không render nếu sai mật khẩu, và API tự chối nếu thiếu mật khẩu) hoạt động độc lập — verify chỉ qua UI mà bỏ qua gọi thẳng API bằng curl rất dễ bỏ sót trường hợp lớp bảo vệ backend bị thiếu.
