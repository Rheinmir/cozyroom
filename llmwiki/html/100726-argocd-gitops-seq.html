T3 · Cài ArgoCD vào namespace mới Claude main

Tạo namespace argocd và áp manifest cài đặt chính thức từ dự án ArgoCD (controller, repo-server, application-controller, Redis, API server) — đây là bước hạ tầng chuẩn, không đụng gì đến namespace cozyroom-k8s đang chạy production. ArgoCD chạy độc lập, chỉ bắt đầu tương tác với cluster khi Application được đăng ký ở bước T4.

T4 · Đăng ký Application — syncPolicy: manual (KHÔNG automated) Claude main

Application CR trỏ vào repo github.com/Rheinmir/cozyroom, path k8s, đích là namespace cozyroom-k8s. Điểm quan trọng nhất của task này: syncPolicy để manual, không bật automated.selfHeal hay prune. Lý do trực tiếp từ audit — postgres-standby trong git đã có bản sửa (DNS name) nhưng live vẫn chạy bản cũ; nếu bật auto self-heal, ArgoCD sẽ tự áp lại spec này ngay, kích hoạt StatefulSet rolling update → pod recreate → init container chạy lại rm -rf data + pg_basebackup — một hành động đụng dữ liệu DB mà CLAUDE.md yêu cầu phải hỏi user trước khi làm.

Với sync thủ công, ArgoCD chỉ hiển thị trạng thái (Synced/OutOfSync) mà không tự hành động — postgres-standby sẽ hiện OutOfSync đúng như audit đã biết, và mọi resource khác (đã reconcile ở Task 1-2) sẽ hiện Synced. Bấm argocd app sync là quyết định của người vận hành, không phải mặc định tự động.

T5 · Verify — site sống suốt quá trình, không sync bất ngờ Claude main

Xác nhận toàn bộ pod production không bị restart ngoài ý muốn trong lúc cài ArgoCD (vì namespace tách biệt và syncPolicy manual), site music.giatbh.io.vn vẫn trả 200 xuyên suốt, và trạng thái Application đúng như dự đoán: mọi resource Synced trừ postgres-standby hiện OutOfSync một cách có chủ đích. Đây là bước đóng vòng lặp audit-trước-khi-tự-động-hoá — chứng minh GitOps không âm thầm phá vỡ production ngay từ ngày đầu.
