01 · Vấn đề

Ảnh Bị Mất Ngẫu Nhiên

Cover art của tracks và YouTube videos biến mất không nhất quán. Tệ nhất khi phát YouTube — radial bubble hiển thị ô trống hoặc placeholder 1×1px mãi mãi, không tự recover.

Triệu chứng quan sát

  • Cover art YouTube biến mất sau khi play lần đầu
  • Local tracks cũng bị mất cover ngẫu nhiên khi resize
  • Radial bubble (bottom vinyl button) hiển thị ảnh placeholder
  • Refresh trang không recover — ảnh corrupt được cache browser 7 ngày
  • Đổi track nhanh → màu gradient sai (stale callback)

Điểm nghi ngờ ban đầu

  • Backend: cover endpoint có cache TTL 7 ngày — lý do ảnh "mất mãi"
  • YouTube: on-demand fetch khi request đầu tiên — dễ race
  • Frontend: new Image() không cleanup khi track thay đổi
  • Scanner: goroutine không timeout, không lock khi download
02 · Root Cause

4 Bugs Tìm Được

Audit độc lập toàn bộ cover fetch pipeline — backend handler, scanner goroutine, frontend hooks. Tất cả đều có chung pattern: concurrent access không được protect.

#BugSeverityFile · LinePattern
1serveResizedImage TOCTOU race — 2 concurrent requests cùng generate cùng resized JPEGCRITICALhandler.go:65os.Stat → os.Create race
2YouTube thumbnail fetch race — 2 concurrent requests cùng fetch và write yt_ID.jpgCRITICALhandler.go:148os.Stat → io.Copy race
3downloadYTThumbnail không timeout — goroutine dùng http.Get không context, có thể treo vĩnh viễnHIGHscanner.go:135Goroutine leak
4Stale image load callback — new Image() không cleanup khi track thay đổi nhanhMEDIUMPlayerBar.tsx:102React useEffect leak

Bug 1 & 2 — TOCTOU Race Pattern

  • Check-then-act không atomic: os.Stat → os.Create
  • Request A và B cùng thấy file chưa tồn tại tại t=0
  • Cả hai gọi os.Create → ghi đồng thời vào cùng file
  • JPEG header bị overwrite giữa chừng → corrupt
  • File corrupt được cache với Cache-Control: max-age=604800
  • Browser lưu vào cache 7 ngày → ảnh mất mãi

Bug 3 — Goroutine Không Timeout

  • http.Get(url) không context → có thể block vĩnh viễn
  • Nếu YouTube chậm/down → goroutine treo indefinitely
  • Nhiều scan → nhiều goroutines treo → memory leak
  • Partial write nếu connection drop giữa chừng → corrupt file
  • Không cleanup partial file khi copy failed

Bug 4 — React stale Image callback

  • Đổi track A → B nhanh: img A vẫn đang load
  • img A onload fires khi đã ở context track B
  • setCoverColors() cập nhật palette của track A vào track B
  • Gradient màu sai, flicker khi skip track liên tục
  • useEffect return không có cleanup → memory leak nhỏ

Tại sao YouTube bị nhiều hơn?

  • Local covers được extract lúc index → ít race hơn
  • YouTube: fetch on-demand khi request đầu tiên đến cover endpoint
  • Nhiều components cùng load cover của 1 video → N concurrent requests
  • PlayerBar + RadialNav + PlayerContext đều request cùng /api/covers/yt:ID
03 · Fix

singleflight Pattern + Cleanup

Giải pháp: dùng golang.org/x/sync/singleflight để đảm bảo chỉ 1 goroutine generate/fetch, còn lại chờ nhận kết quả. Frontend thêm cleanup function.

BEFORE — handler.go:65 (race)
// ❌ TOCTOU race: check và create không atomic
if _, err := os.Stat(resizedPath); err == nil {
    http.ServeFile(w, r, resizedPath)
    return
}
// ← Request A và B đều vào đây đồng thời
out, _ := os.Create(resizedPath)
jpeg.Encode(out, dst, ...)  // ← concurrent write → CORRUPT
out.Close()
AFTER — singleflight
var coverSF singleflight.Group

if _, statErr := os.Stat(resizedPath); statErr == nil {
    http.ServeFile(w, r, resizedPath)
    return
}
// ✅ Chỉ 1 goroutine generate, còn lại chờ
coverSF.Do(resizedPath, func() (any, error) {
    if _, s := os.Stat(resizedPath); s == nil {
        return nil, nil // concurrent đã xong
    }
    out, _ := os.Create(resizedPath)
    jpeg.Encode(out, dst, ...)
    out.Close()
    return nil, nil
})
BEFORE — PlayerBar.tsx:102 (stale)
// ❌ Không cleanup khi track thay đổi
useEffect(() => {
    if (!track) return
    const img = new Image()
    img.src = `/api/covers/${track.album_id}?w=80`
    img.onload = () => {
        // ← fires với context track cũ!
        setCoverColors(colors)
    }
}, [track, setCoverColors])
AFTER — với cleanup flag
// ✅ Cleanup khi track thay đổi
useEffect(() => {
    if (!track) return
    let cancelled = false
    const img = new Image()
    img.src = `/api/covers/${track.album_id}?w=80`
    img.onload = () => {
        if (cancelled) return // bỏ nếu track đã đổi
        setCoverColors(colors)
    }
    return () => {
        cancelled = true
        img.src = '' // abort load
    }
}, [track, setCoverColors])
04 · Compile Fixes
