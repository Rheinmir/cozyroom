Audit: Cover Art Fetch Flow

Cozyroom · 2026-06-22 · Bug: nhạc có nhưng không có hình ảnh phía client

Audit tìm 7 điểm silent fail ở backend và 4 điểm ở frontend. Root cause chính: backend không có fallback image khi cover_path rỗng hoặc file bị mất trên disk. Frontend không đồng nhất về error handling — AlbumPage/ArtistPage có onError → ♪, nhưng SearchPage và PlayerBar background thì không. Case nghiêm trọng nhất: useDominantColor trong PlaylistsPage không set crossOrigin, dẫn đến CORS fail im lặng → màu gradient playlist không bao giờ update.

1. Luồng Cover Chính MEDIUM

Backend tra cover_path từ DB (albums.cover_path) rồi gọi http.ServeFile() để serve file JPEG từ disk. Khi cover_path = "" (ID3 tag không có ảnh, PDF extract fail, v.v.) hoặc file không tồn tại trên disk, API trả HTTP 404 im lặng — không log, không fallback image. Frontend mỗi component xử lý khác nhau: AlbumPage/ArtistPage show ♪, SearchPage show broken image icon, PlayerBar background blank.

Click để pause/resume · indigo = ok · đỏ = fail · cam = warning

2. YouTube Cover Flow MEDIUM

Album ID có prefix yt: được xử lý riêng: backend fetch thumbnail từ YouTube CDN qua 4 quality tiers (maxresdefault → sddefault → hqdefault → mqdefault), cache 7 ngày trên disk, validate JPEG magic bytes (0xFF 0xD8) để detect trường hợp YouTube trả JSON error thay vì ảnh (bug cũ đã fix). Nếu tất cả URLs fail → HTTP 503 — frontend không có handler riêng, browser chỉ thấy broken image; log.Printf có nhưng client không nhận được thông tin lý do.

3. Frontend Color Extraction Bug HIGH

PlayerBar.tsx (canvas extract màu dominant để tạo gradient): set crossOrigin="anonymous" trên Image object → canvas.getImageData() hoạt động đúng. Nhưng PlaylistsPage.tsx (useDominantColor): không set crossOrigin và không có onerror handler. Khi cover trả 404 hoặc bị CORS block → canvas.getImageData() throw SecurityError → uncaught exception → state màu đứng yên ở default #282837 mãi mãi. Không có console warning → rất khó debug, dễ bị bỏ qua.

Click để pause/resume · xanh lá = đúng (PlayerBar) · đỏ = bug (PlaylistsPage)

4. Tổng hợp rủi ro & Đề xuất Fix

7 điểm silent fail backend + 4 điểm frontend. Fix theo thứ tự severity: F-1 (HIGH) trước, sau đó gộp F-2/F-3/B-1/B-2 vào một PR nhỏ, logging B-3/B-4 là bonus.
