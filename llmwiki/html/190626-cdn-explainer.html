CDN là gì?

Tại sao Spotify play nhạc ngay lập tức mà Cozyroom phải đợi — và cách CF Tunnel biến thành CDN miễn phí chỉ với một dòng header.

01 · Khái niệm

CDN là gì?

CDN (Content Delivery Network) là mạng lưới server đặt rải rác khắp thế giới. Thay vì mọi request đều về một server gốc (origin), CDN cache nội dung tại server gần user nhất (gọi là edge node). User nhận data từ cách 10ms, không phải 200ms.

CDN phục vụ từ edge gần user. Lần đầu về origin, từ lần 2 trở đi serve từ cache.

Edge Node là gì?

  • Server vật lý đặt tại các datacenter trên toàn cầu
  • Cloudflare có 300+ edge nodes — Singapore, Tokyo, HCM City, Seoul…
  • User kết nối tới edge gần nhất qua Anycast BGP routing
  • Edge lưu bản copy của file từ origin (cache)

Cache hit vs Miss

  • Miss: edge chưa có file, fetch từ origin về rồi lưu lại
  • Hit: edge đã có, trả thẳng cho user — không cần về origin
  • Sau lần đầu miss, mọi user khác đều hit ⚡
  • TTL (time-to-live) quyết định cache giữ bao lâu
02 · Vấn đề

Không có CDN — mọi request về origin

Khi không có CDN (hoặc CDN không cache), mỗi lần user play nhạc đều phải gửi request xuyên qua internet về tận server gốc. Latency = RTT tới origin, không cải thiện được.

Khi cache bị tắt (Cache-Control: no-cache), CF Edge chỉ là relay — mọi request vẫn xuyên qua về origin.
Cozyroom trước khi fix: Handler http.ServeFile không set Cache-Control rõ ràng → Cloudflare coi response là dynamic, không cache → mỗi lần user play bài, request tunnel về máy bạn. Transcoded paths (?q=320) tệ hơn: explicit no-cache.

Hậu quả không có cache

  • Mỗi lần play = 1 round-trip về origin (~150–300ms RTT)
  • Seek (tua) = nhiều Range request, mỗi cái latency riêng
  • Nhiều user nghe cùng lúc = nhiều kết nối tới origin đồng thời
  • Origin server bị load ngay cả khi nội dung không thay đổi

Tại sao CF Tunnel không tự cache?

  • CF mặc định cache file tĩnh (.js, .css, .png) theo extension
  • /stream/<id> là đường dẫn "dynamic" — CF không cache mặc định
  • Nếu không có Cache-Control: public, CF coi là private/dynamic
  • Cần header rõ ràng để "nói" CF: file này an toàn để cache
03 · Giải pháp

Cache-Control: public — bật CF làm CDN

Thêm Cache-Control: public, max-age=3600 vào response của /stream/<id>. CF edge đọc header này, cache file audio 1 giờ. User play lần 2 → served từ Singapore, không về nhà bạn.

Sau khi bật Cache-Control: public — lần đầu fetch từ origin, lần 2 trở đi served từ CF Edge Singapore.
// backend/internal/api/handler.go

// Trước khi fix: không set Cache-Control
// → CF coi là dynamic, không cache, mỗi request về origin
http.ServeFile(w, r, filePath)

// Sau khi fix: 1 dòng header
w.Header().Set("Cache-Control", "public, max-age=3600")
http.ServeFile(w, r, filePath)
// → CF cache 1 giờ, mọi request sau served từ edge ⚡

Tại sao an toàn để cache?

  • /stream/<id> — track ID là hash, content không đổi nếu ID không đổi
  • Deterministic: cùng URL = cùng bytes mọi lúc
  • max-age=3600 = cache 1 giờ, đủ cho session nghe nhạc
  • Nếu file đổi → scanner tạo ID mới → URL mới → cache miss tự động

Transcoded paths (320kbps) — giữ no-cache

  • ?q=320 transcodes lossless → MP3 on-the-fly qua ffmpeg
  • Streaming response không có Content-Length → CF không cache được dù có header
  • lossless-clean tương tự — stream không biết trước kích thước
  • Chỉ lossless passthrough (http.ServeFile) có Content-Length → CF cache được
04 · Thực tế Cozyroom

CF Tunnel + Cache = CDN miễn phí

Cozyroom dùng Cloudflare Tunnel để expose service ra internet. CF Tunnel đi qua Cloudflare's network — cùng network có 300+ edge nodes. Bật cache = biến CF Tunnel thành CDN thật, không tốn thêm gì.

Full request path Cozyroom. Sau khi cache hit tại CF Edge, phần còn lại (cloudflared → nginx → backend → disk) chỉ chạy lần đầu tiên.
Tương tự Spotify: Spotify dùng Akamai/CF CDN có trả tiền. Cozyroom dùng CF Tunnel miễn phí và chỉ cần thêm Cache-Control: public, max-age=3600 — CF tự động cache và serve từ edge gần user. Kết quả tương đương về mặt cơ chế, khác về quy mô.

Trước khi fix (no-cache)

  • Mỗi lần play: ~150–300ms latency (RTT về nhà)
  • CF Tunnel chỉ relay, không lưu gì
  • 10 người nghe = 10 connections về origin
  • Bandwidth từ nhà ra internet bị chiếm nhiều

Sau khi fix (public, max-age=3600)

  • Lần 1: ~200ms (miss, CF fetch + cache)
  • Lần 2+: ~10–30ms từ CF Edge gần user ⚡
  • 10 người nghe cùng bài = 1 miss + 9 hits
  • Bandwidth nhà không bị ảnh hưởng sau lần đầu
