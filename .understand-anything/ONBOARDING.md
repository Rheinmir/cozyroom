## 1. Project Description

**Cozyroom** is a self-hosted personal media server built for one owner, deployed on a 3-node K3s cluster running on Windows 11 WSL2 (Tailscale Citus distributed Postgres across nodes). It covers:

- **Music streaming** — gapless dual-Audio preloading, smart radio, playlists, HLS audio fallback
- **YouTube integration** — search (yt-dlp), live stream proxy (4h signed-URL cache), download to local library, cover thumbnail backfill
- **AI assistant** — agentic chat (Claude/OpenRouter), 23 MCP tools (`play_track`, `search_library`, `web_search`, `browse_url`, `get_lyrics`, etc.), persistent key-value memory, AI token usage stats
- **Video** — HLS streaming, ebook (PDF/EPUB) reader, comics reader
- **GitHub Trending** — daily AI-scored trending repos chart (`TrendingChartMode`)
- **Bots** — Telegram, Discord, Microsoft Teams bridge
- **Observability** — Prometheus metrics endpoint, Grafana dashboards

**Languages:** Go (backend), TypeScript/React (frontend), Python (tooling/harness)  
**Key dependencies:** pgx/v5 (Postgres), hls.js, @tanstack/react-query, vite-plugin-pwa, yt-dlp, ffmpeg, ffprobe  
**Deployment:** K3s (3 WSL2 nodes) · Cloudflare Tunnel (cloudflared) → nginx sidecar (port 18080) → K8s service

## 4. Key Flows

### 4.1 Music Playback (Happy Path)
```
User clicks track →
  PlayerContext.startTrack(track) →
    trackRef.current = track (sync, before setTrack) →
    setTrack(track) →
    audioRef.current.src = "/api/stream/" + track.id →
    audioRef.current.play() →
  Backend GET /api/stream/:id →
    handler.go:stream() →
      serve byte-range from musicPath/track.filePath →
      OR transcode.go:TranscodeToOpus() if FLAC/WAV (ffmpeg pipe) →
  PlayerBar updates progress via timeupdate event →
  At 90% duration: preload nextAudioRef.src = next track URL →
  At track end: swap audioRef ↔ nextAudioRef (gapless)
```

### 4.2 YouTube Stream
```
User searches YouTube →
  GET /api/youtube/search?q=... →
    youtube.go:search() →
      yt-dlp --flat-playlist dump (JSON) →
      return [{id, title, uploader, duration, thumbnail}] →
User clicks YT result →
  PlayerContext.startYTTrack(ytResult) →
    GET /api/youtube/stream/:id →
      youtube.go:stream() →
        check cache (4h signed-URL cache) →
        yt-dlp --get-url (extract direct stream URL) →
        wrap through cloak-proxy →
        return {streamURL, coverURL} →
    ytStreamUrl = streamURL →
    audioRef.current.src = streamURL
```

### 4.3 YouTube Download
```
User initiates download →
  POST /api/youtube/download {id, title, uploader} →
    youtube.go:download() →
      dlPath = h.ytDownloadPath (or h.musicPath fallback) →
      yt-dlp --write-thumbnail --format bestaudio -o dlPath/%(id)s.%(ext)s <url> →
      albumID = id8hex(id8hex(uploader) + title) →
      thumbSrc = dlPath/body.ID+".jpg" →
      thumbDst = coversDir/albumID+".jpg" →
      os.Copy(thumbSrc → thumbDst) →
      os.Remove(thumbSrc) →
      IndexFileWithMetadata(dlPath/body.ID+ext) →  ← registers in DB
    return {albumID}
```

### 4.4 Library Scan
```
Trigger: startup or POST /api/scan →
  scanner.go:Scan(musicPath) →
    filepath.Walk(musicPath) →
    for each audio file:
      tags = dhowden/tag.ReadFrom(file) →
      artistID = id8hex(lowercase(trim(artist))) →
      albumID = id8hex(id8hex(artist) + title) →
      trackID = id8hex(albumID + filename) →
      cover = tags.Picture() → write to coversDir/albumID.jpg →
      upsert artist, album, track (ON CONFLICT(id) DO NOTHING for albums) →
    for YouTube files (baseName len == 11):
      if !exists(coversDir/albumID.jpg):
        go downloadYTThumbnail(baseName, dest)  ← async
```

### 4.5 AI Agent Loop
```
User sends message →
  POST /api/ai/chat {messages, model, tools} →
    ai.go:chat() →
      loop (max 12 rounds):
        call LLM (Claude or OpenRouter) with messages + tool_definitions →
        if response.tool_calls:
          for each tool_call:
            mcp/registry.go:dispatch(tool_name, args) →
              match to one of 23 MCP tools →
              execute (play_track → PlayerContext signal, search_library → DB query, web_search → chromedp, ...) →
              append tool_result to messages →
        else:
          return final text response →
      return messages + usage stats
```

### 4.6 Cover Serving
```
GET /api/covers/:id →
  handler.go:cover() →
    validate id format (hex16 or "yt:ytid") →
    if yt: prefix:
      singleflight.Do(id, func() {
        fetch https://i.ytimg.com/vi/<ytid>/maxresdefault.jpg
        fallback: hqdefault → mqdefault
      }) →
      return JPEG (503 if all fail — triggers frontend retry) →
    else:
      serveResizedImage(coversDir, id) →
        resize to 400px if > 800px (golang.org/x/image) →
        Cache-Control: max-age=31536000
```

## 7. Guided Tour

### Step 1 · Project Overview
`README.md`, `CLAUDE.md`, `docker-compose.yml`

Cozyroom is a self-hosted personal media server: music with gapless playback, AI assistant via MCP, YouTube stream/download, HLS video, ebooks/comics. React frontend with Spotify-like purple/glassmorphism UI. Deployed on K3s (3 WSL2 nodes) with Citus distributed Postgres. The `CLAUDE.md` encodes LLM behavioral rules — always read it first.

### Step 2 · Server Entry Point
`backend/cmd/server/main.go`

This file wires all dependencies: opens Postgres connection pool, constructs repository implementations, builds usecase layer, registers the HTTP router (routes.go), launches background goroutines (library scan, enrichers, trending fetch), and starts cron + bots. It's the composition root — if you're tracing where something is initialized, start here.

### Step 3 · HTTP Routing & Middleware
`backend/internal/api/routes.go`, `backend/internal/api/handler.go`

`routes.go` registers ~60 endpoints grouped by domain (`/api/artists`, `/api/albums`, `/api/tracks`, `/api/stream/:id`, `/api/youtube/*`, `/api/ai/*`, `/api/covers/:id`, `/api/playlists`, `/api/trending`, `/api/scan`, `/api/stats`, `/api/lyrics/:id`, `/api/video/*`, `/api/ebook/*`, `/api/comics/*`). `metricsMiddleware` and `panicRecovery` wrap all handlers. Non-API routes fall through to the SPA handler (serves `frontend/dist/index.html`).

### Step 4 · Database & Repository Layer
`backend/internal/db/db.go`

`db.go` wraps `pgx/v5` with a connection pool (MaxConns=20) and helper methods for query/queryRow/exec. All Postgres repositories in `backend/internal/repository/postgres/` implement domain interfaces from `backend/internal/domain/`. Handlers never touch SQL directly — they call interface methods. Citus distributed Postgres: coordinator at `db-adapter` (HAProxy), worker nodes at `postgres` and `postgres-standby`.

### Step 5 · Library Scanner
`backend/internal/library/scanner.go`

Walks `musicPath`, reads audio tags (artist, album, title, year, genre) via `dhowden/tag`. Derives deterministic 8-byte hex IDs: `id8 = SHA256(lowercase(trimspace(s)))[:8]`. `artistID = id8(artist)`, `albumID = id8(id8(artist) + albumTitle)`, `trackID = id8(albumID + filename)`. Extracts embedded cover art. YouTube files detected by `len(baseName) == 11` (YT ID length) — if cover missing, launches async `downloadYTThumbnail` goroutine. Upserts to Postgres with `ON CONFLICT(id) DO NOTHING` for albums/artists.

### Step 6 · Audio Streaming & Transcoding
`backend/internal/transcode/transcode.go`

`GET /api/stream/:id` serves byte-range audio directly for MP3/AAC/OGG. For FLAC/WAV/AIFF, `transcode.go` pipes through `ffmpeg -i <input> -c:a libopus -f webm -` streaming to the HTTP response. HLS module (`backend/internal/hls/`) manages video segmentation. Cover art served via `cover()` handler with `singleflight` dedup and JPEG resize (`golang.org/x/image`).

### Step 7 · YouTube Integration
`backend/internal/api/youtube.go`

`YouTubeHandlers` struct holds `db`, `musicPath`, `ytDownloadPath`, `coversDir`, `cloakProxyURL`. Search: `yt-dlp --flat-playlist -j <url>` dumps JSON, returns to frontend. Stream: `yt-dlp --get-url` extracts direct stream URL, wraps through `cloak-proxy` (evades YT bot detection), caches 4h. Download: yt-dlp writes to `ytDownloadPath`, copies thumbnail `thumbSrc → coversDir/albumID.jpg`, then calls `IndexFileWithMetadata`. `albumID = id8hex(id8hex(uploader) + title)`.

### Step 8 · AI Agent & MCP Tools
`backend/internal/mcp/registry.go`, `backend/internal/api/ai.go`

`mcp/registry.go` defines 23 tools as JSON Schema objects (name, description, parameters). `ai.go` runs the agentic loop: prepend system prompt → call LLM (Claude 3.5 Sonnet or OpenRouter model) → parse tool_calls → dispatch each to registry → append results → loop (max 12 rounds). Persistent key-value memory stored in Postgres `ai_memory` table. Token usage tracked per-model in `ai_usage` table (feeds AIStatsPage).

### Step 9 · Frontend Player State
`frontend/src/PlayerContext.tsx`

`PlayerContext` is the heart of the frontend. It holds: `track` (active track), `queue` (smart radio or playlist), `ytStreamUrl` (resolved YT stream URL), `volume`, `progress`, `duration`, `isPlaying`, `lyrics`. Gapless playback: dual Audio elements, preload next track at 90% of current. YouTube ↔ local track transitions: `trackRef.current` synced synchronously before `setTrack` to avoid stale closure in `timeupdate` handler. `localStorage` persists queue + volume between sessions.

### Step 10 · Frontend Pages & Components
`frontend/src/pages/AIAssistantPage.tsx`, `frontend/src/components/PlayerBar.tsx`, `frontend/src/components/RadialNav.tsx`

`ArtistsPage` and `AlbumDetailPage` handle library browsing with mirror reflection CSS effects. `AIAssistantPage` renders streaming chat with tool-call display and model selector. `TrendingChartMode` shows GitHub trending with AI scores on a Nightingale rose chart. `PlayerBar` is the persistent bottom bar; YT covers retry up to 4× (2/4/6/8s backoff) because backend returns 503 on thumbnail fetch failure. `RadialNav` is the polar-segment desktop navigation.

### Step 11 · K8s Deployment
`k8s/backend.yaml`, `k8s/cloudflared.yaml`

Backend deployment: Go binary container with PV mounts at `/data` (covers, HLS) and `/youtube` (yt-dlp downloads); `/music` read-only NFS. Frontend deployment: nginx serving React dist + Service Worker. `cloudflared.yaml`: cloudflared container + nginx sidecar (`proxy_buffering off; proxy_request_buffering off; memory 128Mi`) — CF remote config hardcodes `localhost:18080` so the sidecar MUST exist. Prometheus in `observability/` namespace; Grafana dashboard at internal Grafana URL.

## 9. ID Derivation Reference

All entity IDs are deterministic — same input always produces same ID:

```
artistID  = SHA256(lowercase(trim(artistName)))[:8]  hex
albumID   = SHA256(lowercase(trim(artistID + albumTitle)))[:8]  hex  
trackID   = SHA256(lowercase(trim(albumID + filename)))[:8]  hex
ytAlbumID = SHA256(lowercase(trim(id8hex(uploader) + title)))[:8]  hex
```

The function `id8`/`id8hex` is identical in `scanner.go` and `youtube.go` — same SHA256 truncate logic, not a coincidence.

Cover file: `coversDir/<albumID>.jpg`  
Stream URL: `/api/stream/<trackID>`  
Cover URL: `/api/covers/<albumID>`

1. **Nginx sidecar must run alongside cloudflared** — CF remote config hardcodes `localhost:18080`, cannot be overridden via ConfigMap
2. **`proxy_buffering off` on nginx sidecar** — audio streams are large; buffering causes OOMKill at 128Mi
3. **PV `k8s-data` hostPath is immutable** — current live path is `/tmp/k8s-cozyroom-data`, not what YAML says
4. **Album `ON CONFLICT DO NOTHING`** — scanner won't update existing albums; enriched covers survive re-scans
5. **`trackRef.current` must sync before `setTrack`** — async useEffect sync causes stale closure in `timeupdate` → 0:00 display bug
6. **YT cover 503 vs 200** — backend returns 503 (not 200+placeholder) on thumbnail fail so frontend `onError` fires and retries
7. **SW renamed sw→sw2** — CF was caching `sw.js` bypassing nginx no-cache; rename forces re-registration
8. **`id8hex` == `id8`** — both are `SHA256(lowercase(trim(s)))[:8]`; same function, two names
